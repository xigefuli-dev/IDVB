# 自定义地图与原生地图对齐规范

本文档描述当前生产实现。生产逻辑位于主项目 `Features/Maps`；现有 Probe 仅用于采样、标注和离线回放。

## 运行约束

- 本轮只渲染一楼。二楼识别成功后安全隐藏，直到二楼参考图和锚点完整。
- 只允许固定旋转、等比缩放和平移，不允许非等比缩放、自由仿射或透视。
- 当前 28 张地图固定旋转均为 `0°`。
- 地图身份可以持久化；固定缩放/旋转按地图和窗口签名持久化；视口平移永不持久化。
- 每次开图必须用本次画面重新求平移。关闭后立即隐藏并废弃本次平移。
- `ForceBestRecognitionResult` 只保留为候选调试开关，不能自动锁定、显示错误背景或复用上一次开图的平移。

## 地图 schema v4

地图包位于：

```text
%LOCALAPPDATA%\IDVBuff\Maps\
  maps.json
  <map-id>\
    floor-1.png|jpg|jpeg
    floor-2.png|jpg|jpeg
    floor-1-recognition.png
    floor-1-overlay.png
```

一楼 `FloorRecognitionProfile` 包含：

- `RecognitionRegion`：相对原图的归一化识别区域。
- `RecognitionPixelWidth/Height`：识别图像素尺寸。
- `ValidMapBounds`：识别图坐标中的有效地图边界。
- 必需的大门、侧门锚点和任意辅助锚点。
- `WholeImageIgnoreRegions`：参考图静态忽略区。

读取 schema v1–v3 时原子迁移到 v4。已有锚点保持不变；缺少
`ValidMapBounds` 时使用完整识别图范围。当前 28 张地图因此无需重新标门。

## 强类型坐标和变换

运行时区分：

- `MapReferencePoint`：完整参考图像素。
- `MapViewportPoint`：原生地图视口内部像素。
- `MapScreenPoint`：物理屏幕像素。
- `MapViewportOrigin`：视口左上角在参考图中的位置。

`MapSimilarityTransform` 把参考图映射到屏幕：

```text
screen = uniformScale * rotate(reference, fixedRotation) + translation
```

它提供正向、逆向、有限值检查和视口边界约束。玩家完整地图位置只能通过已锁定变换的逆变换得到。

## 标定、开图会话和玩家状态

数据分三层：

- `MapAlignmentCalibration`：地图版本、参考尺寸、固定缩放/旋转、客户端尺寸、DPI、视口尺寸和置信度。
- `MapOpenSession`：本次开图状态、锁定变换、视口原点、定位方式、失效原因和玩家状态。
- `MapPlayerState`：视口、屏幕、完整地图坐标、置信度和观察时间。

`MapSessionSnapshot` 是只读诊断快照。玩家更新接口不能接收、返回或修改背景变换。

## 开图状态机

```text
Closed
  → OpeningDetected
  → WaitingForStableFrames
  → IdentifyingMap
  → CoarseLocating
  → FineLocating
  → Confirming
  → Locked
```

异常状态为 `LowConfidence`、`Lost` 和 `RecalibrationRequired`。

- 热键只表达可能打开/关闭的意图。
- 前台游戏中使用已校准楼层小区域以 5Hz 检查地图存在。
- 打开后至少等待 250ms；之后每 50ms 采帧。
- 高饱和动态像素和设置中的固定忽略区先被遮罩。
- 归一化帧差不高于 `0.015` 且连续三帧稳定后才配准。
- 最长等待 3 秒；超时进入 `LowConfidence`，覆盖层保持隐藏。本次开图不自动重试，下一次开图输入才会启动新的扫描与对齐。
- 关闭意图立即取消高成本任务、清除覆盖层和本次变换；视觉连续缺失两次也进入 `Closed`。

锁定后：

- 玩家检测最高 10Hz。
- 背景只读验证 1Hz。
- 窗口位置、句柄、分辨率、DPI 和视口签名检查 2Hz。
- 连续三次背景失败或窗口签名变化才重新配准。
- 玩家移动、玩家检测失败和玩家隐藏绝不触发背景配准。
- 待处理楼层请求为容量 1 的最新帧队列；旧排队帧被替换。

## 配准降级顺序

只对当前已选地图加载缓存。没有已选地图时，快捷扫描或手动识别负责建立地图 ID。

1. 双锚点
   - 验证门类型、身份、方向、距离、模板分数和几何残差。
   - 无标定时求等比缩放和平移；有标定时固定缩放和旋转，只求平移。
   - 测得缩放偏离标定超过 3% 时拒绝为原生地图缩放变化。
   - 双门结果必须再通过静态结构、有效边界和玩家先验复核。
2. 单锚点
   - 必须已有可信固定缩放/旋转。
   - 单门只提出平移候选，随后必须通过结构、边界、地图 ID 和玩家先验复核。
   - 复核不足时进入无锚点结构定位，不能直接锁定。
3. 无锚点
   - 只在当前地图中搜索平移。
   - 有玩家先验时，先用“玩家位置减半个视口参考尺寸”预测视口原点并限制到有效边界。
   - 预测只缩小搜索和参与验证，不能直接成为结果；局部失败后扩大到整张参考图。
   - 从未建立可信缩放时拒绝锁定，等待双门或人工标定。
4. 全部失败
   - 覆盖层保持隐藏。
   - 不使用上一次开图平移，不强制显示最优候选。

## 结构预处理、缓存和搜索

参考图和实时视口生成灰度归一化图、CLAHE 图、结构占用图和边缘图。

- 默认去除四周 2% 边框。
- 玩家、门点、辅助锚点和固定忽略区向外扩张 6px 后遮罩。
- 高饱和路线/标记、小组件和分离 UI 被过滤。
- 参考缓存包含 1.0/0.5/0.25 边缘金字塔、AKAZE 特征、重复区域图和距离变换。
- 缓存键包含地图版本和算法版本；内存只保留有界的当前地图缓存。

粗定位合并 0.25 倍距离模板候选和 AKAZE 平移投票，最多保留 5 个独立平移候选。特征匹配使用比率筛选、平移聚类和离群排除；重复区域特征不参与投票。

精定位在候选附近执行全分辨率 Chamfer、边缘覆盖、占用覆盖和四分区一致性优化，然后执行仅平移 ECC。整数局部修正限制在候选附近；ECC 修正不超过约 ±3px。缩放搜索在生产开图路径默认禁用。

结构缓存位于：

```text
%LOCALAPPDATA%\IDVBuff\MapAlignmentCache\
```

调试图只在显式启用时写入 `MapAlignmentDebug`。所有 `Mat`、位图、截图和被替换帧都由拥有者及时释放。

## 置信度和锁定

可用证据按缺失项移出分母的方式加权：

- 锚点与几何 20%
- AKAZE/RANSAC/平移聚类 15%
- 粗候选与第一、第二差距 10%
- Chamfer、边缘和占用 25%
- ECC 与精修改善 10%
- 边界和玩家先验 10%
- 多帧稳定性 10%

非有限变换、越界、地图 ID 不一致、锚点几何错误和缩放异常是硬否决。

- `≥ 0.82`：无硬否决可锁定。
- `0.62–0.82`：连续三帧平移差不超过 3 屏幕像素后锁定。
- `< 0.62`：拒绝并隐藏。

`Locked` 到关闭期间，背景缩放、旋转和平移对象不再被玩家链路修改。

## 对局状态、玩家模板和检测

- 应用启动时对局状态固定为“已结束”，不会持久化上一局的玩家身份。
- 外置控件层要求先选择 1–4 号玩家再开始对局；结束时停止实时链路并清空本局地图、玩家和对齐会话。
- `Assets/player_01.png`–`player_04.png` 是固定玩家模板，状态页不再要求手动校准玩家图标。
- 运行时只识别本局选中的序号，先在上次玩家位置附近做多尺度模板匹配，并用主色、轮廓和面积复核。
- 连续五次失败后扩大到整个视口。
- 置信度不低于 `0.70` 时，用锁定变换逆变换到完整地图坐标，并限制在有效边界。
- 超过 500ms 无可信检测时只隐藏玩家标记，背景不动。

## 覆盖层和诊断

- 背景严格裁剪到原生地图视口。
- 锁定后缓存静态背景位图；玩家更新只合成对应序号图片和状态，不重新读盘缩放地图。
- 外置控件层是可交互的独立置顶窗口；状态/地图层继续点击穿透，手动框选层继续独占全屏输入，三者不共用窗口。
- 窗口签名变化先隐藏，再重新配准，避免旧屏幕坐标残留。
- 状态页显示会话状态、地图/楼层、定位方式、候选、AKAZE 内点、ECC、视口原点、固定变换、置信度、玩家完整地图坐标和失效原因。

## Probe 和真实验收

Probe 继续用于真实样本：

```text
dotnet run --project IDVBuff.MapAlignment.Probe -- capture --delay 3 --out <样本目录>
dotnet run --project IDVBuff.MapAlignment.Probe -- floor --delay 3 --repeat 100
dotnet run --project IDVBuff.MapAlignment.Probe -- label --sample <sample.json>
dotnet run --project IDVBuff.MapAlignment.Probe -- match --sample <sample.json> --scale 1
dotnet run --project IDVBuff.MapAlignment.Probe -- batch --dir <样本根目录>
```

合成测试只能证明变换、状态机、降级、裁剪、缓存和资源所有权。像素误差、p95 延迟和长期内存标准必须使用真实 28 图回放集验证；没有真实标注样本时不得宣称已达到这些指标。
