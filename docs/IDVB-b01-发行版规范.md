# IDVB b01 发行版规范

**状态：** 待实施基线
**目标产品：** Identity Vision Bridge（IDVB）
**公开发行版本：** b01.1-26.8.4.1129（示例；实际时间由发布流程生成）
**适用平台：** Windows 10 1809（17763）及以上、Windows 11，x64
**安装语言：** 简体中文（zh-CN）

## 1. 目标与边界

b01 将 IDVB 交付为一个可安装、可升级、可卸载、可验证的 Windows 桌面应用。发行包必须为用户提供中文图形安装体验，支持选择安装位置、可选创建桌面快捷方式，并明确处理运行依赖、升级和卸载。

本规范中的“IDVB”是唯一的**公开名称**：安装包、安装向导、开始菜单项、桌面快捷方式、卸载项、安装目录、日志、文档、发行文件名和校验文件均不得向用户显示 `IDVBuff`。

现有源码中的 `IDVBuff` 命名空间、项目目录和本地数据目录属于兼容性实现细节。b01 不因品牌重构而迁移这些业务代码标识；但最终发布的主程序、安装目录和面向用户的文件名必须使用 `IDVB`。若内部程序集仍含旧名称，必须在发布检查中记录为临时兼容项，且不得在安装界面、快捷方式、卸载列表或发行文件名中暴露。

不在 b01 范围内：MSIX/商店发布、x86/ARM64 安装包、云端自动更新服务、静默企业部署以外的远程管理能力。

## 3. 发行架构

### 3.1 安装器技术选型

b01 使用 **Inno Setup 6** 作为唯一的安装器工程，安装脚本、语言文件、依赖安装逻辑和构建脚本均纳入仓库。不得继续使用 IExpress、`Install.cmd`、`Install.ps1`、`Uninstall.cmd` 或 `Uninstall.ps1` 作为用户安装入口。

选型要求：

- 使用官方简体中文语言文件，所有自定义字符串为简体中文。
- 使用 Inno Setup 标准欢迎、目录、组件、任务、准备安装、安装进度、完成和卸载页面；不显示 PowerShell 或命令提示符窗口。
- 卸载器必须是 Inno Setup 生成、随安装目录部署的原生可执行文件（标准形态为 `unins000.exe`），且由“设置”、开始菜单和安装器维护入口直接启动。不得把 `.cmd`、`.bat`、`.ps1`、`wscript` 或经 `cmd.exe`/`powershell.exe` 间接启动的脚本注册为 `UninstallString`。
- 正式 b01 包内不得包含 `Install.cmd`、`Install.ps1`、`Uninstall.cmd`、`Uninstall.ps1` 这四类旧入口脚本；它们不属于有效载荷、不得复制进安装目录，也不得出现在发布目录。
- 安装范围为“仅当前用户”，默认不请求管理员权限；只有安装到受保护目录时，才由安装器请求提升权限或提示改用可写目录。
- 安装器脚本必须由 `installer/Build-Release.ps1` 生成和调用，输出仅落在 `artifacts/release/`。
- 构建机必须固定 Inno Setup 版本，并在构建日志中记录其版本；缺少编译器时构建失败且给出中文可操作错误。

### 3.2 目录与交付物

```text
artifacts/release/
  IDVB-Setup-b01-x64.exe
  IDVB-Setup-b01-x64.exe.sha256
  IDVB-b01-x64-manifest.json
  IDVB-b01-x64-release-notes.md
```

清单 JSON 至少包含：产品名、公开版本、数值版本、目标 RID、构建提交、构建时间（UTC）、安装器 SHA-256、签名状态、主程序 SHA-256、依赖版本和构建工具版本。构建中间文件只能位于 `artifacts/release/.work/`，构建成功后删除。

安装器必须嵌入应用有效载荷和离线依赖，不依赖安装时联网下载。安装器与主程序在正式对外分发前须进行 Authenticode 签名并启用时间戳；未签名构建只能标为内部测试包，不能标为正式 b01 发行件。

## 4. 依赖策略

| 依赖 | b01 策略 | 安装行为 | 验收 |
| --- | --- | --- | --- |
| .NET 运行时 | 自包含发布 | 随应用安装，不单独安装全局运行时 | 断网、无预装 .NET 的干净系统可启动 |
| Windows App SDK | 自包含发布 | 随应用安装，不依赖共享 Windows App Runtime | 干净系统可启动，目录内完整包含所需原生库 |
| Microsoft Edge WebView2 Runtime x64 | 离线安装包随安装器携带 | 先检测；缺失或版本不满足时静默安装，并显示“正在安装网页组件”进度 | 无 WebView2 的干净系统中安装后可用 |
| Visual C++ 2015–2022 x64 | 安装器携带离线 redistributable | 先检测；缺失时安装 | OpenCV 等原生库加载成功 |
| OpenCV 原生库 | 随应用发布 | 复制到应用目录，不单独注册 | 所需 `OpenCvSharpExtern.dll` 与依赖存在且可加载 |

依赖安装包必须来自供应商官方可再分发渠道，记录文件名、版本、SHA-256、许可证和来源 URL 到依赖锁定清单。依赖安装返回码 `0`、`3010`（需要重启）视为成功；其它返回码中止安装、保留错误日志，并回滚本次已复制的应用文件。需要重启时，完成页必须以中文提示“组件已安装，建议重启 Windows 后再启动 IDVB”，不得自动重启。

安装器在安装前完成 x64 系统检查、Windows 最低版本检查、磁盘空间检查（有效载荷大小 + 20% + 500 MiB）和运行中进程检查。检查失败必须用中文说明原因、所需条件和下一步操作。

### 5.2 快捷方式与任务栏

- 开始菜单快捷方式始终创建：`Identity Vision Bridge\Identity Vision Bridge.lnk`；工作目录为安装目录，图标为 `IDVB.exe,0`。
- “创建桌面快捷方式”由用户选择；更新安装不得重复创建或删除用户主动保留的同名快捷方式。
- Windows 10/11 没有适用于普通桌面安装器的受支持、可靠的“静默固定到任务栏”公共 API。b01 仍展示“固定到任务栏（安装完成后引导操作）”选项：选择后，完成页显示中文一步提示“启动 IDVB 后，在任务栏图标上右键，选择‘固定到任务栏’”。安装器不得调用未公开 Shell 动词、注册表破解或模拟点击来伪造固定操作。
- 若未来获得受支持的 Microsoft API 或企业策略部署通道，可在新版本将该选项改为自动执行；变更前需修订本规范和兼容性测试。

## 6. 安装、升级与回滚

### 6.1 新安装

1. 校验安装器自身签名（正式包）并创建日志。
2. 检查系统、空间、运行进程与目标目录权限。
3. 安装缺失依赖；依赖失败即停止，不复制主程序。
4. 解压应用到同卷临时目录，例如 `%LocalAppData%\Programs\.IDVB-installing-<GUID>`。
5. 验证临时目录内的文件清单、主程序哈希和 `IDVB.exe` 存在。
6. 原子替换为目标目录，创建选定快捷方式与卸载信息。
7. 运行无界面自检（加载主程序集、检查关键原生库存在），成功后显示完成页。

### 6.2 升级与降级

安装器检测同一稳定产品 ID 的现有版本：

- 已安装版本低于 b01：执行就地升级，保留用户数据、用户选择的安装目录和桌面快捷方式偏好。
- 已安装版本等于 b01：提供“修复安装”和“卸载”选项；修复重建程序文件与必需依赖，不删除用户数据。
- 已安装版本高于 b01：默认阻止降级，并显示“已安装较新版本”；仅内部测试包可通过明确命令行开关允许降级。
- 升级前若 IDVB 正在运行，提示关闭后重试；不得强制结束用户进程。

替换前将旧应用目录移入同卷备份目录。任一文件复制、验证、快捷方式或注册失败时，恢复旧目录和原有卸载项；失败日志必须保留。成功后删除备份目录。

### 6.3 安装日志与退出码

日志位置：`%LocalAppData%\IDVB\Logs\Installer\IDVB-Setup-b01-<timestamp>.log`。日志不得记录用户文件内容、令牌、账号或其他敏感信息。

静默参数规范为 `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /LOG=<path>`；支持 `/DIR="<absolute-path>"` 和 `/TASKS="desktopicon"`。无人值守调用须返回：`0` 成功、`3010` 成功但建议重启、`1` 可预期失败、`2` 意外错误、`3` 用户取消。GUI 模式取消不弹出错误信息。

## 7. 卸载规范

### 7.1 Windows 设置集成（强制）

IDVB 必须可由用户**直接**在 Windows 设置中卸载，且不依赖开始菜单、桌面快捷方式或安装包仍然存在：

- Windows 10：`设置 > 应用 > 应用和功能` 搜索“Identity Vision Bridge”或“IDVB”，点击“卸载”即可启动卸载器。
- Windows 11：`设置 > 应用 > 已安装的应用` 搜索“Identity Vision Bridge”或“IDVB”，在产品项的“…”菜单中点击“卸载”即可启动卸载器。
- 两个入口必须启动同一中文图形卸载程序 `unins000.exe`。它是 Inno Setup 编译生成的卸载可执行文件，不依赖 PowerShell、命令提示符、批处理文件或用户机器上的脚本执行策略。

实现必须使用当前用户的 Windows 标准“添加/删除程序”（ARP）注册表位置：

```text
HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\IDVB_is1
```

这是 b01“仅当前用户安装”范围下 Windows 10、Windows 11 设置均应枚举的位置。Inno Setup 必须负责创建及在卸载完成时删除该项；禁止以自定义 PowerShell 或注册表脚本伪造该入口。卸载键值至少满足下表，实际路径和版本从构建变量生成，不能手写为旧产品名。

| 注册表值 | 要求 |
| --- | --- |
| `DisplayName` | `Identity Vision Bridge b01` |
| `DisplayVersion` | `b01`（公开版本） |
| `Publisher` | 已确认的发行者名称；不能使用 `User Name` 或占位文本 |
| `InstallLocation` | 用户最终选定的 IDVB 安装目录 |
| `DisplayIcon` | `IDVB.exe,0` 的绝对路径 |
| `UninstallString` | 带引号的 `unins000.exe` 绝对路径；不得包裹在 `cmd.exe`、`powershell.exe` 或脚本中 |
| `QuietUninstallString` | 同一原生卸载器加受支持静默参数的绝对命令 |
| `EstimatedSize` | 应用及卸载器已安装大小，单位 KB |
| `NoModify`、`NoRepair` | 按 b01 策略设为 1，设置页不得显示不可用的修改/修复入口 |

安装完成后，安装器须重新读取上述注册表项，并确认 `UninstallString` 目标文件存在且为安装器生成的 `unins000.exe`。若注册失败，安装视为失败并回滚，不能显示“安装完成”。卸载完成后，卸载器须确认该键已删除；如果 Windows 设置列表因系统缓存未即时刷新，完成页可提示用户关闭并重新打开设置，但不得把缓存延迟误报为卸载失败。

“设置 > 应用”和开始菜单中的“卸载 Identity Vision Bridge”均使用上述同一卸载器。卸载项必须显示发布者、版本、安装日期、图标、预计大小和可执行卸载命令。

卸载流程：

1. 显示“卸载 Identity Vision Bridge b01”确认页，并检测运行中的 IDVB。
2. 提供“保留我的 IDVB 数据与设置”复选框，**默认勾选**。生产数据目录为 `%LocalAppData%\IDVB`；首次启动时，旧 `%LocalAppData%\IDVBuff` 的内容会安全迁移到新目录，且绝不覆盖新目录已有数据。
3. 删除开始菜单快捷方式及本安装器创建的桌面快捷方式；仅删除目标指向本安装目录的快捷方式，绝不删除同名但指向其他程序的文件。
4. 删除应用目录、卸载注册表项、安装器自身和本次安装日志以外的临时文件。
5. 若用户取消“保留数据”，先显示二次确认：“此操作会永久删除 IDVB 的本地数据与设置，无法恢复。是否继续？”确认后才删除经 `AppDataPaths` 确认的目录。
6. 依赖（WebView2、VC++、全局运行时）默认为共享组件，卸载 IDVB 时不得移除。

卸载程序运行于应用目录中时，必须通过安装器自身的延迟删除机制或受控临时清理器删除剩余文件；不得使用无边界的递归删除命令。删除目标须解析为安装目录或经确认的数据目录的子路径。文件被占用时显示中文可恢复提示，保留残留和卸载日志，而不是宣称卸载完成。

## 8. 安全、隐私与可靠性

- 默认目录仅当前用户可写；不向 `Program Files`、`Windows`、系统 PATH、文件关联或开机启动项写入内容。
- 任何安装、修复、升级和卸载操作都限制在已验证的安装目录、临时目录和数据目录内。
- 不在安装程序中以 `ExecutionPolicy Bypass` 执行用户可编辑脚本；安装逻辑编译进安装器或只调用随包、经哈希校验的依赖安装程序。
- 所有发布文件计算 SHA-256；发行说明列出哈希校验示例及签名发布者。
- 安装器显示的产品名、发布者和版本必须与签名证书、清单 JSON、应用“关于”页一致。

## 9. 构建与发布流程

1. 执行测试并确认工作树中与发行无关的改动不被打包。
2. 以 `Release|x64` 执行自包含发布，设置 `AssemblyName=IDVB`、`WindowsAppSDKSelfContained=true`，并写入与公开版本对应的数值版本（例如 `26.8.4.1129`）和产品版本（例如 `b01.1-26.8.4.1129`）。
3. 对发布目录执行文件白名单检查：必须有 `IDVB.exe`、运行配置、必要托管程序集、Windows App SDK 原生库、WebView2 Loader、OpenCV 原生库、许可证与安装清单；不得有 PDB、测试程序集、源码、旧安装/卸载脚本或 `IDVBuff.exe`。
4. 获取并校验锁定的离线依赖文件哈希。
5. 由 Inno Setup 编译 `installer/IDVB.iss`，生成规范名称的安装包；随后生成校验、清单和发行说明。
6. 对安装包和主程序签名、时间戳，再重新计算并写入 SHA-256 清单。
7. 在干净 Windows 虚拟机执行第 10 节验收，所有通过后才将 `artifacts/release/` 中的四项文件作为 b01 发布件。

旧的 IExpress 构建脚本与 PowerShell 安装/卸载脚本在新流程通过验收后删除，避免被误用；删除前不得覆盖用户工作树中无关改动。

## 11. 实施完成定义

b01 仅在以下条件全部满足时视为“发行版重构完成”：安装器工程和构建脚本已纳入版本控制；所有 R01–R17 均有可复现的测试记录；正式发布物使用 IDVB 品牌与 b01 版本；安装、升级、修复和卸载均有中文 UI、日志和失败恢复；发行目录没有旧 IExpress 产物；并且未在未经专项验证的情况下破坏现有 `IDVBuff` 内部兼容性。
